# wheel_leg_demo 项目PRD

更新：2026-10-15。本文只记录当前范围、职责和验收要求；运行命令见[开发与演示手册](开发与演示手册.md)，图解与视频见[项目讲解](轮足项目.html)。

## 1. 目标与范围

实现：A点轮式出发 → 绕障到E → 停车变足式 → 上两级楼梯到X → 恢复轮式 → 绕障到B停车。

- 重点：全局路径规划、轮式局部规划、足式局部规划与任务串联。
- 已知地图、障碍与楼梯；位姿来自Gazebo仿真反馈。
- 使用运动学执行和预设变形展示；必须检查占用范围、碰撞、可达性及运动限制，不用跳位置穿越障碍冒充成功。
- 不开发感知建图、定位、移动障碍预测、下楼、自平衡、接触力/力矩控制或真机部署。几何和运动学验证不等于动力学稳定性验证。

## 2. 技术与职责

ROS 2 Humble、Gazebo Classic 11、C++17、CMake/ament_cmake、colcon；Python只写launch。沿用公司镜像；RViz可选，不引入完整Nav2。

| 模块 | 输入 → 输出 | 职责边界 |
|---|---|---|
| 全局规划 | 地图、占用范围、A/B/E/X → 有序参考路径与轮/足区段 | 上下平台分别二维栅格A*，用固定E→X足式连接段拼接；输出路径，不安排到达时间 |
| 轮式局部 | 当前位姿/速度、轮式参考段、障碍 → 短时轨迹及线/角速度 | 用已有Ceres实现精简TEB，联合优化位姿和时间；A→E、X→B复用，不是完整上游移植 |
| 足式局部 | 当前机身/双足、踏面与约束 → 交替落脚序列、足端/机身轨迹 | 足步A*＋分段五次多项式；一次规划E→X，首版不做在线足步重规划 |
| 任务调度 | 路段、模式、反馈 → 行驶/变形/停止指令 | 依据到位、对齐、停车和双足位置切换；不以固定时间代替到达判断 |
| Gazebo执行 | 规划轨迹、变形指令 → 动作显示与仿真反馈 | 跟随规划，不自行决定路线，不开发真实底层控制 |

规划与调度位于同一`/global_planner`节点，执行为Gazebo插件；逻辑职责不要求拆成多个节点。

## 3. 模型、场景与点位

- 双轮共用横杆，两条手臂下放作足；轮组竖直收起。机身0.54×0.30×0.18 m，轮径0.28 m、轮距0.42 m，两段臂各0.28 m。
- 脚掌0.18×0.10×0.035 m；落脚点指足面中心，相对踝轴前移0.05 m。轮式占用按0.60×0.78 m保守检查。
- 外形与比例已验收；参考材料位于`lab/reference/yapemg/`，当前实现独立维护。

| 区域 | world坐标范围（m） |
|---|---|
| 下平台 | x∈[-6,2]、y∈[-3,3]，地面z=0 |
| 楼梯 | x∈[2,2.7]、y∈[-2,2]；两阶，每阶高0.17、深0.35、宽4 |
| 上平台 | x∈[2.7,10.7]、y∈[-3,3]，地面z=0.34 |

两处静止障碍分别位于两段轮式路段；平台边界与楼梯侧壁不可通行。

| 点 | 地面投影(x,y,z)，m | 用途 |
|---|---|---|
| A | (-4.5,-0.9,0) | 初始化/复位；实际规划起点读取当前仿真位姿 |
| E | (1.6,-0.9,0) | 入口停车、对齐、变足式 |
| X | (3.3,-0.9,0.34) | 机身及双足进入上平台后恢复轮式 |
| B | (9,-0.9,0.34) | 终点停车 |

四点yaw=0朝+x；长度用米、角度用弧度。地面z与机身高度分开。模型、楼梯或点位变更需重新确认可达性与验收范围。

## 4. 运行与保护要求

1. 使用同一world坐标与仿真时间；暂停不推进动作。服务返回Accepted只表示接收，完成/失败以状态为准。
2. 全局检查通行性；局部检查将执行的整段轨迹，包括机器人轮廓、足面、部件可达性与非法碰撞，不能只检查中心点。
3. 速度、加速度、安全余量、停车阈值与超时写入`config/demo.yaml`并随结果保存。五次轨迹段间位置、速度、加速度连续。
4. E到位、对齐、停车后变形；X确认机身和双足进入平台且轮组有展开空间后恢复轮式。足式入口yaw需满足≤0.005 rad；自动任务对轮式对齐使用更严格门槛。
5. 无路、局部持续受阻、不可落脚、反馈失效或超时，停止推进并报告原因；可恢复受阻只有限重规划，不无限重试或跳过失败路段。
6. 停止取消后续任务；复位回A、清除测试障碍，不自动开始。正常自动演示不调用测试摆位或阶段2预设climb代替规划。

## 5. 架构与流程（报告用）

```text
已知地图/楼梯 + 起终点
          |
          v
全局A* → 参考路径 + 模式区段
          |
          v
       任务调度 ──────────→ 变形指令
          |                    |
    +-----+-----+              |
    v           v              |
轮式精简TEB   足步A*＋五次轨迹   |
    +-----+-----+              |
          v                    |
  碰撞/限制/可达性检查          |
          +----------+---------+
                     v
             Gazebo运动学执行
                     |
                     v
                仿真反馈/状态
                     └──→ 局部规划与任务调度
```

```text
加载场景与机器人 → 全局规划
  → A→E轮式避障 → 到位、对齐、停车
  → 变足式 → 足步规划/检查 → E→X迈步
  → 机身及双足进入平台 → 恢复轮式
  → X→B轮式避障 → 到达、停车、DONE

任一阶段不可行/反馈异常/超时 → 停止推进、记录原因
可恢复的路径受阻 → 有限重规划；仍失败 → FAILED
```

## 6. 分阶段验收

各阶段先自测并提供命令与结果，再由用户验收后进入下一阶段。

| 阶段 | 验收重点 | 状态 |
|---|---|---|
| 1 机器人与场景 | 外形、比例、两级楼梯与障碍正确；显示10秒无异常跳变；重置后模型仍存在 | 用户已确认 |
| 2 动作展示 | 双向变形、轮式前进≥1 m、预设足式上两阶；动作连续，忙碌/停止/复位有效 | 用户已确认 |
| 3.0 地图与四点 | 扩图、四点标记、A初始化、E/X空间与可达性 | 用户已确认 |
| 3.1 全局规划 | A→E轮、E→X足、X→B轮；轮廓不穿障/越界；更换A/B可重规划；堵塞/非法目标明确失败 | 用户已确认 |
| 3.2 轮式局部 | 两段独立到达、停车；误差≤0.10 m、朝向≤5°；满足限速/余量；新增静止障碍绕行、堵塞停车 | 已同意进入3.3 |
| 3.3 足式局部 | 足步A*生成交替序列；足面安全落脚；整段连续可达、不穿模、满足限制；机身/双足到X；不可落脚拒绝执行 | 用户已确认 |
| 4 完整自动演示 | 一次开始串联全流程；恢复轮式后前进≥1 m；终点误差≤0.10 m；同起点连续成功3次；停止/复位/失败有效 | 自测通过，待用户验收 |

证据保存在`doc/results/`：阶段汇总CSV、案例原始数据与参数、独立检查JSON、代表图/视频。成功与失败案例分别保存；保留当时版本与指标，不以截图替代数值检查。用户验收状态与自测结论分开。

- `doc/项目讲解.html`离线打开，六章覆盖概览、进入容器/启动、场景、规划、视频、验收；命令区分本机和三个容器终端。
- 提供命令复制、点位说明、实际记录回放、足端侧视、视频跳转/清晰度切换与全屏演示。原理示意与实际结果明确区分。

- 源码与运行参数以代码/YAML为准；操作命令维护在手册；PRD只维护要求与验收状态，流水只维护重要结论。
- 不更换公司镜像或放宽权限，不新增包装启动脚本。新增依赖或扩大功能范围先说明并确认。
