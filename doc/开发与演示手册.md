# 开发与演示手册

更新：2026-10-16。项目功能已实现；阶段4自测通过，待用户最终验收。范围见[PRD](项目PRD.md)，讲解与视频见[HTML](轮足项目.html)。

## 1. 进入容器：本机终端

```bash
systemctl is-active docker
# 若不是active：sudo systemctl start docker
xhost +SI:localuser:root
docker start hfun_humble_cuda_dev
docker exec -it -e DISPLAY="$DISPLAY" hfun_humble_cuda_dev bash --norc
```

本机`/home/hfun/norin/lab`挂载到容器`/root/Projects`。详细镜像与重建命令见[运行与依赖说明](../README.md)。

## 2. 准备环境：每个新容器终端执行

```bash
export PATH=/usr/local/sbin:/usr/local/bin:/usr/sbin:/usr/bin:/sbin:/bin
source /opt/ros/humble/setup.bash
source /usr/share/gazebo/setup.sh
export ROS_DOMAIN_ID=76
export ROS_LOCALHOST_ONLY=1
# 本机现有容器中的位置；同事使用自己的克隆目录
cd /root/Projects/gazebo/gazebo_manual/wheel_leg_demo
```

两条ROS通信设置仅对当前终端及其启动的程序生效；三个终端保持一致。ROS开发使用系统环境，不进入Conda；ROS 2不需要roscore。

## 3. 编译与打开场景：容器终端1

```bash
colcon build --symlink-install --base-paths src --packages-select wheel_leg_demo
source install/setup.bash
ros2 launch wheel_leg_demo demo.launch.py
```

修改C++/CMake后重新编译；修改模型、配置或launch后重启仿真。仅服务端使用`gui:=false`。同一Gazebo端口只运行一套仿真，关闭窗口不等于关闭服务端。

## 4. 启动规划与任务：容器终端2

另开本机终端，用第1节docker exec进入同一容器，执行第2节环境命令，再执行：

```bash
source install/setup.bash
ros2 launch wheel_leg_demo planning.launch.py task:=true
```

该模式同时启用全局、轮式、足式和任务调度；不另开其他planning节点。

## 5. 开始完整演示：容器终端3

另开终端进入同一容器，执行第2节环境命令及`source install/setup.bash`。

复位并查看状态：

```bash
ros2 param set /global_planner task.case_name manual
ros2 service call /wheel_leg_demo/reset_demo std_srvs/srv/Trigger "{}"
ros2 topic echo /wheel_leg_demo/task_status --qos-durability transient_local
```

看到`READY`后按Ctrl+C退出查看，再开始：

```bash
ros2 service call /wheel_leg_demo/start_demo std_srvs/srv/Trigger "{}"
ros2 topic echo /wheel_leg_demo/task_status --qos-durability transient_local
```

正常顺序：全局规划 → A→E轮式绕障 → 停车对齐/变足式 → 足步规划/E→X上楼 → 恢复轮式 → X→B绕障停车 → `DONE`。Accepted仅表示接收；失败看`FAILED`及reason。同名manual会覆盖上次manual记录，保留多次运行请换case_name，不使用正式run_1～run_3名称。

## 6. 停止、复位与退出

在终端3按需单独执行：

```bash
ros2 service call /wheel_leg_demo/demo_status std_srvs/srv/Trigger "{}"
ros2 service call /wheel_leg_demo/stop_demo std_srvs/srv/Trigger "{}"
ros2 service call /wheel_leg_demo/reset_demo std_srvs/srv/Trigger "{}"
```

停止取消后续动作：轮式制动，足式/变形保持展示位姿；复位回A、清除测试障碍，不自动开始。STOPPED或中途停止后，复位再开始。

退出顺序：stop_demo并确认停止 → 在规划和仿真终端分别Ctrl+C → `exit`离开容器。需要关闭容器时在本机执行`docker stop hfun_humble_cuda_dev`。

仿真暂停/恢复（容器终端3）：

```bash
ros2 service call /pause_physics std_srvs/srv/Empty "{}"
ros2 service call /unpause_physics std_srvs/srv/Empty "{}"
```

## 运行结果位置

默认新结果在运行用户的 `~/.local/state/wheel_leg_demo`，不在源码doc/results。全局、轮式、足式、任务分别在global/baseline、wheel_local、foot_local、task子目录。`doc/results`保留历史验收材料。

```bash
# 替代第4节命令：将本次结果集中到指定目录
ros2 launch wheel_leg_demo planning.launch.py task:=true results_dir:="$PWD/results"
```

路径与克隆部署规则见[README](../README.md)。下面第8节列出的CSV、图表和视频均为历史归档。

## 7. 文件与参数入口

| 路径 | 职责 |
|---|---|
| `urdf/robot.urdf.xacro`、`worlds/two_steps.world` | 模型、平台、台阶、障碍 |
| `config/demo.yaml` | 地图点位、占用范围、规划/动作限制与任务超时 |
| `src/global_planner.cpp` | 全局二维A*与模块入口 |
| `src/teb_optimizer.cpp`、`src/wheel_local.cpp` | 轮式TEB、轨迹检查与执行指令 |
| `include/wheel_leg_demo/foot_planner.hpp`、`src/foot_local.cpp` | 足步A*、五次轨迹、足式执行接口 |
| `src/task_runner.cpp`、`src/demo_node.cpp` | 任务串联、Gazebo运动学执行 |
| `launch/`、`CMakeLists.txt` | 启动、编译和运行资源安装；不安装doc/results |

四点为world地面投影、yaw均0：A(-4.5,-0.9,0)、E(1.6,-0.9,0)、X(3.3,-0.9,0.34)、B(9,-0.9,0.34)，单位m。机身高度由形态计算。楼梯每阶高0.17、深0.35、宽4 m。

模型尺寸、C++几何参数、YAML占用范围必须同步；落脚点为足面中心，相对踝轴前移0.05 m。足式按已知踏面一次规划完整E→X；位姿来自仿真，当前不包含平衡或接触力控制。

## 9. 独立模块调试（按需）

先结束自动任务和旧planning进程。终端1保留Gazebo，终端2加载环境与install后运行：

```bash
ros2 launch wheel_leg_demo planning.launch.py wheel_local:=true foot_local:=true global_output_dir:=/tmp/wheel_leg_demo_global
```

临时全局结果写到/tmp。终端3加载环境与install后，先设置案例名，避免覆盖正式基线：

```bash
ros2 param set /global_planner wheel.case_name manual
ros2 param set /global_planner foot.case_name manual
```

### 全局与轮式

每个独立案例开始前先停止局部任务、复位、生成完整全局参考：

```bash
ros2 service call /wheel_leg_demo/stop_local std_srvs/srv/Trigger "{}"
ros2 service call /wheel_leg_demo/stop_footsteps std_srvs/srv/Trigger "{}"
ros2 service call /wheel_leg_demo/reset std_srvs/srv/Trigger "{}"
ros2 service call /wheel_leg_demo/plan_global std_srvs/srv/Trigger "{}"
```

A→E或独立X→B二选一；X摆位不表示完成上楼：

```bash
# A→E
ros2 service call /wheel_leg_demo/run_lower std_srvs/srv/Trigger "{}"
# 独立X→B：重新执行上面的案例准备后，逐条执行
ros2 service call /wheel_leg_demo/prepare_upper std_srvs/srv/Trigger "{}"
ros2 service call /wheel_leg_demo/run_upper std_srvs/srv/Trigger "{}"
```

查看全局/轮式状态：

```bash
ros2 topic echo /wheel_leg_demo/planning_status --once --qos-durability transient_local
ros2 topic echo /wheel_leg_demo/local_status --once --qos-durability transient_local
```

新增静止障碍使用`/wheel_leg_demo/add_local_obstacle`；堵塞使用`block_lower`或`block_upper`，测试后`clear_test_obstacle`。均为std_srvs/srv/Trigger服务，完整调用格式同上；堵塞预期FAILED_BLOCKED，不是成功到达。只验证全局时可不启用两个local参数，更换起终点通过`/global_planner`的start、goal及use_feedback_start参数。

### 足式E→X

重新执行案例准备命令，再逐条执行：

```bash
ros2 service call /wheel_leg_demo/prepare_entry std_srvs/srv/Trigger "{}"
ros2 service call /wheel_leg_demo/to_leg std_srvs/srv/Trigger "{}"
ros2 topic echo /wheel_leg_demo/status
```

等待`DONE_TO_LEG`，按Ctrl+C结束查看，再规划并执行：

```bash
ros2 param set /global_planner foot.block_first_tread false
ros2 service call /wheel_leg_demo/plan_footsteps std_srvs/srv/Trigger "{}"
ros2 service call /wheel_leg_demo/run_footsteps std_srvs/srv/Trigger "{}"
ros2 topic echo /wheel_leg_demo/foot_status --qos-durability transient_local
```

仅plan返回成功后才能run；DONE表示到X，正常为8步、约36秒。到X后保持足式，需要时用`to_wheel`恢复轮式。`prepare_entry`是测试摆位，不表示完成A→E。

不可落脚测试：在E完成变形后，将`foot.block_first_tread`设true，再plan，预期NO_FEASIBLE_FOOTSTEPS且run被拒绝；测试后恢复false。停止用`stop_footsteps`，复位回A后需重新规划。阶段2的drive/climb为预设动作，不代替规划。

## 10. 常见问题

| 现象 | 处理 |
|---|---|
| systemctl提示非systemd | 当前在容器内；Docker服务在本机终端管理 |
| Gazebo Address already in use | 结束旧启动终端的仿真；不要只关闭窗口，也不要盲目杀其他进程 |
| 看见局域网其他节点 | 每个新终端设置域76和LOCALHOST_ONLY=1，旧节点需停止后按新环境重启 |
| 动作不动/提示忙碌 | 查task_status或status，确认仿真未暂停；不要重复发送Accepted后的任务 |
| 原版RViz的D-Bus报错复现 | 检查持久AppArmor策略hfun-ros-gui；当前专用策略已修复，不使用绕过脚本 |
| 模型/环境参数改动后结果不一致 | 同步world、Xacro、YAML与C++几何；重启并重新验收相关部分 |

Gazebo界面与文件编辑基础见Gazebo 操作手册（本机通用资料，未纳入此仓库）；阶段结论与整理记录见[更新流水](更新流水.md)。
